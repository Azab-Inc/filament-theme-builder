# Filament demo showcase gap research

**Reviewed:** 2026-10-10  
**Scope:** Official Filament demo at `https://demo.filamentphp.com/login`, this repository's Filament 5 demo, installed package sources, `SPECS.md`, and `TICKETS.md`. This is a surface inventory for theme preview, not a claim of complete upstream coverage.

## Sources and method

- Opened the official [Filament demo login](https://demo.filamentphp.com/login), signed in using the credentials presented by that page, and inspected its welcome/feature-index page and linked surface routes. No data-changing actions were performed.
- The official welcome page identifies the running version as Filament 5.10.1, links to the [official Filament documentation](https://filamentphp.com/docs) and [official repository](https://github.com/filamentphp/filament), and presents a 62-feature index linked to live routes. These observed routes are cited below as primary UI evidence. The official demo's source code was not exposed by the site, so claims about its internals are avoided.
- Compared those observations to the repository's `demo/app/Filament` implementation, installed `demo/vendor/filament` APIs where present, and the approved contract in [`SPECS.md`](../../SPECS.md) and [`TICKETS.md`](../../TICKETS.md).

## Current repository baseline

- This is a real Filament 5.9+ app (`demo/composer.json`, `filament/filament: ^5.9`) with a discoverable public panel at `/demo/admin`. [`AdminPanelProvider`](../../demo/app/Providers/Filament/AdminPanelProvider.php#L26-L65) configures the default Filament dashboard, the built-in `AccountWidget` and `FilamentInfoWidget`, profile, and the preview bridge. There are no app-defined `demo/app/Filament/Pages` or `Widgets` files at present; consequently there is no custom dashboard widget/chart implementation.
- Core ecommerce data/resources, badges on table columns, images, money and statuses, grouped navigation and relationships are already called out as implemented in [FTB-009B](../../TICKETS.md#ftb-009b). For example, the common resource table exposes standard view/edit and bulk-delete actions, and its rows have entity-dependent columns/filters ([`EntityResourceTable`](../../demo/app/Filament/Support/EntityResourceTable.php#L19-L46)). Products use three relation managers ([`ProductResource`](../../demo/app/Filament/Resources/Products/ProductResource.php#L49-L55)). These are a sound foundation, but mostly CRUD defaults rather than the richer, deliberately distinct showcase surfaces requested in [SPECS §16](../../SPECS.md#16-showcase-coverage).
- Icon variety is especially weak: the resources inspected all assign `Heroicon::OutlinedRectangleStack` as their navigation icon (example: [`ProductResource`](../../demo/app/Filament/Resources/Products/ProductResource.php#L28-L33)); the panel sets only an amber primary color and no brand name/logo configuration ([`AdminPanelProvider`](../../demo/app/Providers/Filament/AdminPanelProvider.php#L30-L50)).
- The only custom page action found in the inspected application code is an `Items` URL action alongside the default edit action on order view ([`ViewOrder`](../../demo/app/Filament/Resources/Orders/Pages/ViewOrder.php#L15-L22)). Other CRUD pages use common create/view/edit/delete patterns. The installed Filament action API supports action types and modal rendering (e.g. `Action::iconButton()`, `grouped()`, `link()`, `renderModal()` in [`Action.php`](../../demo/vendor/filament/actions/src/Action.php#L288-L316), [`Action.php`](../../demo/vendor/filament/actions/src/Action.php#L778-L790)); having those APIs installed does not mean this demo currently showcases them.
- `FilamentPanelTest` verifies the public dashboard, bridge and built-in profile/login behavior, but does not assert custom charts, widgets, action/modals, notification variants, icon variety, navigation counts or branding ([`FilamentPanelTest.php`](../../demo/tests/Feature/FilamentPanelTest.php#L16-L49)).

## Proposed ticket decomposition

The most suitable work already exists as FTB-011 through FTB-018; the gaps do not require a new umbrella ticket. Keep the repo's demo-first gate in place: [FTB-009A → FTB-009B → FTB-010](../../TICKETS.md#dependency-map) are marked done, so showcase work may proceed subject to each ticket's explicit blockers.

1. **FTB-011 — Forms & Schemas:** add feature fixtures for visually distinct layouts/controls and deterministic filled/disabled/error/focus states; do not repeat equivalent resource CRUD forms.
2. **FTB-012 — Tables:** add table showcases for visual treatments and interactive controls missing from shared CRUD (grouping/summaries/column toggles/reorder/selection/actions/empty/loading/mobile); use seeded ecommerce records.
3. **FTB-013 — Infolists:** add an explicit read-only showcase for rich text, media/images, badges/icons, repeatable entries and section/layout treatments.
4. **FTB-014 — Actions, Modals, Notifications:** own custom action variants/grouping/tooltips, modal and slide-over layouts, confirmation/forms/footer actions, and notification variants. Ensure notification unread-count treatment has a fixture. Keep forced-open state tooling itself in FTB-016.
5. **FTB-015 — Widgets, Navigation, Search, Auth/Tenant:** add custom dashboard stat/chart/table widgets; differentiated sidebar icons, grouped nav, active/collapsed states and count badges; demonstrate global search, breadcrumbs/sub-navigation/tabs and controlled profile/auth/tenant UI.
6. **FTB-016 — Forced states:** extend the deterministic controls to open showcase modals and notifications and force action/widget/navigation/table/form states without persistent demo-data mutation.
7. **FTB-017 — Icon packs and semantic replacement:** implement icon-system choices and selected semantic overrides using actual Filament configuration/render behavior, not CSS-only glyph replacement.
8. **FTB-018 — Branding/runtime configuration:** add brand name, light/dark logo, favicon, logo sizing/typography and relevant panel layout options; classify immediate emulation versus refresh/export-only behavior.
9. **Coverage and verification:** record every resulting visually distinct first-party surface in COVERAGE.md (FTB-032/039), then add deterministic Playwright visual snapshots through FTB-033. Existing relevant acceptance criteria should be tightened with the explicit examples above; avoid broadening FTB-009 domain scope.

All showcase fixtures should be real Filament output and deterministic, as required by [SPECS §16–17](../../SPECS.md#16-showcase-coverage) and [FTB-016](../../TICKETS.md#ftb-016). The official demo illustrates useful candidate surfaces, but it is not itself the complete coverage contract: SPECS §16 and COVERAGE.md remain the project's stated source of scope.
